Backend Reference
=================

This reference maps backend files to responsibilities and API behavior.
Paths are relative to repo root.

Chat Service (`backend/chat`)
-----------------------------
`backend/chat/server.js`
- Express server for RAG chat.
- CORS uses `CORS_ORIGIN` with support for explicit and wildcard origins.
- `POST /api/rag-chat` streams `text/plain` output.
- `POST /api/finance-podcast` is available for AI podcast generation (frontend page currently marked Coming Soon).
- Health endpoints: `/healthz`, `/readyz`.

`backend/chat/rag.js`
- Main orchestration for retrieval, ranking, prompt, and stream output.

`backend/chat/retrieval.js`
- Embedding + vector retrieval from Postgres.
- Keyword fallback when OpenAI embeddings are unavailable.

`backend/chat/db.js`
- `pg.Pool` from `DATABASE_URL`.

Claimcheck Service (`backend/claimcheck`)
-----------------------------------------
`backend/claimcheck/server.js`
- Express server for claim flow + admin endpoints.
- Exposes `GET /api/finance-news`.
- CORS uses `CORS_ORIGIN` with support for explicit and wildcard origins.
- Health endpoints: `/healthz`, `/readyz`.

`backend/claimcheck/routes/claim.routes.js`
- `POST /api/claim-check`
- `POST /api/claim-evidence`
- `POST /api/claim-story`
- `GET /api/admin/claims?limit=<n>` (requires `x-admin-token`)
- `PATCH /api/admin/claims/:claimId` (requires `x-admin-token`)

`backend/claimcheck/services/*.js`
- OCR, EXIF, matching, story analysis, coverage checks, image checks, Supabase persistence.
- OpenAI usage:
  - `image.service.js`: incident-image consistency + quality checks.
  - `coverage.service.js`: policy coverage reasoning with heuristic fallback.
  - `story.service.js`: final narrative consistency decision.
- Story fallback safety:
  - If OpenAI output is missing/invalid, claim decision falls back to partial/manual-review path.
- Geo behavior:
  - Geo tagging uses fallback chain:
    1) EXIF GPS metadata
    2) OCR parsing of visible coordinate text in image
    3) OpenAI vision parsing of visible coordinate text (if `OPENAI_API_KEY` is set)

State and Persistence
---------------------
- Transient claim step state: in-memory `claimStore`.
- Durable admin/reporting state: Supabase `claims` table.

API Contract Summary
--------------------
`POST /api/rag-chat`
- Body: `{ question, language?, domain?, details? }`
- Response: streaming plain text.

`POST /api/claim-check` (multipart)
- Field: `pdf`
- Response: `{ valid, message, claimId?, extracted? }`

`POST /api/claim-evidence` (multipart)
- Fields: `claimId`, `claimType`, `fir`, `photos`
- Response: `{ status, message, ... }`

`POST /api/claim-story`
- Body: `{ claimId, story }`
- Response: `{ eligible, claimCode?, level?, riskLevel?, explanation?, reasons? }`
- OpenAI behavior:
  - With `OPENAI_API_KEY`: OpenAI is used for coverage + story checks.
  - Without key (or AI failure): heuristic/manual-review fallback is used.

`GET /api/admin/claims`
- Header: `x-admin-token`
- Query: `limit` (optional, positive integer)

`PATCH /api/admin/claims/:claimId`
- Header: `x-admin-token`
- Body: `{ adminDecision, adminNotes }`

`GET /api/finance-news`
- Response: `{ status, updatedAt, from, to, articles[] }`

Required Production Variables
-----------------------------
Chat service:
- `NODE_ENV=production`
- `DATABASE_URL`
- `OPENAI_API_KEY`
- `CORS_ORIGIN`

Claim service:
- `NODE_ENV=production`
- `SUPABASE_URL`
- `SUPABASE_SERVICE_ROLE_KEY`
- `ADMIN_TOKEN` (non-default)
- `CORS_ORIGIN`
- `NEWS_API_KEY`

Recommended local run variables:
- `CHAT_PORT=5175`
- `CLAIM_PORT=5174`
