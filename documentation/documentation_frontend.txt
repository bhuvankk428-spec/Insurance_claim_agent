Frontend Documentation
======================

Overview
--------
Frontend is a Vite + React app with Tailwind styling.
Main flows:
1. Policy advisor chat (RAG)
2. Claim checker (policy + evidence + story)
3. Admin dashboard for claim review
4. Plan builder + plan dashboard
5. Finance news view

Entry Point and Routing
-----------------------
`src/main.jsx`
- React root setup.

`src/App.jsx`
- Route map:
  - `/` -> LoginEntry
  - `/register` -> RegisterForm
  - `/choose` -> ChooserPage
  - `/chatbot` -> Chatbot
  - `/claim-checker` -> ClaimChecker
  - `/plan` -> PlanPage
  - `/plan-dashboard` -> PlanDashboard
  - `/finance-news` -> FinanceNews
  - `/ai-finance-podcast` -> AIFinancePodcast (Coming Soon placeholder)
  - `/claim-story/:claimId` -> ClaimStoryChatbot
  - `/claim-result/:claimId` -> ClaimResult
  - `/admin-dashboard` -> AdminDashboard
  - `/about`, `/help`, `/faq`, `/contact`

Configuration
-------------
Vite environment variables:
- `VITE_CHAT_API_URL`: chat backend URL (required in production)
- `VITE_CLAIM_API_URL`: claim backend URL (recommended in production)
- `VITE_API_URL`: fallback for claim/admin endpoints
- `VITE_ADMIN_EMAIL` or `VITE_ADMIN_EMAILS` (comma-separated), `VITE_ADMIN_TOKEN`

Runtime behavior:
- On localhost, frontend falls back to local backend URLs.
- In production, missing API URLs show explicit UI errors.
- Admin dashboard requires `VITE_ADMIN_TOKEN` only outside localhost.

Authentication
--------------
`src/firebase.js`
- Firebase init + auth exports.

`src/components/auth/LoginForm.jsx`
- Firebase login (email/password + Google).
- Admin redirect uses `adminAuth.js` email match helper after successful Firebase login.

`src/components/admin/adminAuth.js`
- Reads admin email allowlist from `VITE_ADMIN_EMAILS` or `VITE_ADMIN_EMAIL`.
- Ignores known placeholder emails and falls back to `admin@qk.ai` if config is missing.
- Exposes admin token used by admin API calls.

Policy Advisor (Chatbot)
------------------------
`src/components/Chatbot.jsx`
- Calls `POST /api/rag-chat` on chat backend.
- Streams plain text response chunks.
- Sends `language` (`en`, `hi`, `te`, `kn`) and optional `domain` + `details`.
- Auto-detects insurance domain from query when domain is set to "Any".
- Supports speech synthesis voice playback and mute toggle.
- Shows clear error if `VITE_CHAT_API_URL` is missing in production.

Claim Checker Flow
------------------
`src/components/ClaimChecker.jsx`
- Step 1: `POST /api/claim-check` (policy PDF)
- Step 2: `POST /api/claim-evidence` (FIR + photos)
- Stores returned `claimContext` in browser `sessionStorage` keyed by `claimId`
- On success navigates to story page.

`src/components/ClaimStoryChatbot.jsx`
- Step 3: loads saved `claimContext` and `POST /api/claim-story` with `{ claimId, story, claimContext }`
- Navigates to result page with decision data.
- If backend OpenAI analysis is unavailable, backend may return partial/manual-review outcome instead of full approval.

Admin Dashboard
---------------
`src/components/admin/AdminDashboard.jsx`
- Requires Firebase auth + admin email route guard.
- Loads claims via `GET /api/admin/claims?limit=<n>` with `x-admin-token`.
- Updates decisions via `PATCH /api/admin/claims/:claimId`.
- Supports client-side search (claim ID, code, email, owner, status).
- Supports load-more pattern by increasing `limit`.
- Supports export to printable PDF summary from filtered claim list.
- Shows explicit configuration errors for missing production env.

Finance News
------------
`src/components/FinanceNews.jsx`
- Calls `GET /api/finance-news` on claim backend.
- Shows latest items and refreshes automatically every 24 hours.
- Supports manual refresh and fallback image handling.

AI Finance Podcast
------------------
`src/components/AIFinancePodcast.jsx`
- Route `/ai-finance-podcast` is currently a Coming Soon page.
- No backend call is made from this page until feature release.

Known Constraints
-----------------
- In-progress claim context is preserved for the active browser session using `sessionStorage`, which makes the claim flow production-safe on serverless backends.
- If the browser session storage is cleared or the user switches devices mid-flow, Step 1 may need to be restarted.
- Production setup must align frontend and backend admin tokens.
- Current admin authorization model is not role-claim based; frontend email checks should be treated as UX gating, not strong backend authorization.
- Geo-tag status depends on backend geo fallback chain: EXIF GPS -> OCR coordinate text parsing -> OpenAI vision coordinate parsing (if key configured).
